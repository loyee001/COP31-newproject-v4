# 绿茵计划 ShadePath

导入校园底图、确认人行步道，在统一预算下计算不同日期和时刻的种植方案与遮荫收益。网页支持简体中文、English、Türkçe；本次不包含 Godot 页面或工程，未部署网站。

## 打开与使用

双击 `ShadePath-preview.html` 即可离线使用。macOS 可双击 `启动网页预览.command`，Windows 可双击 `启动网页预览.bat`。

在“太阳与阴影”视图中：

1. 点击“导入 PNG / JPG / WebP / JSON”，选择校园底图，自动提取道路、交叉口、树冠与绿地区域。
2. 在原图上查看候选结果，拖动节点或树冠修正位置，删除误识别部分；遗漏道路可补画，也可点选路面颜色后重新识别。
3. 确保底图北朝上，填写实际图宽并应用比例。初始图宽只是模型比例，需用实测尺寸校准。
4. 确认后，路网和现有树进入阴影及统一预算优化计算。

识别在本机完成，适合道路与植被颜色清晰的平面图。结果是待确认的候选：浅色广场和建筑入口可能与道路混淆，图片也不能自动判断道路是否允许行人通行；建筑高度不从图片推断。只有确认的步道与树木参与计算，草坪不作为遮阳树。树高使用模型默认值，需要现场资料校准。“管理步道”默认收起，展开后可改名、调整净宽和人流权重、重新描画或删除。PNG、JPG、WebP 图片最大 8 MB、1600 万像素，校园 JSON 最大 16 MB。

多条步道共用一个预算。同一棵树可以服务多条步道，费用只计算一次；重叠路段不重复计分。左侧常驻太阳控制、预算和优化前后比较；拖动侧栏分隔线可调整宽度，最多占页面一半。

拖动时刻或选择 09:00 / 12:00 / 15:00，自动方案会按所选出发时刻重新计算树位，早晚通过太阳方向反投影寻找能将阴影投到步道的位置。手动方案保留树位，只更新阴影与收益。地图可切换遮阳效果、种植布局，以及优化前后；全天曲线的竖虚线标出当前时刻。

手动种树、91% 收益方案和完整费用清单收在侧栏“更多选项”中。种植坐标图显示候选点与已选树，可点击或用键盘选择查看坐标。

## 右侧 3D 场景

初次打开载入用户指定的清华大学平面图示意，识别路网与树冠仍需确认。右侧默认拖动平移地图及对焦中心、滚轮缩放、双击对焦；“旋转视角”按钮或 Alt 拖动可旋转。“跟随行人”重新对准人物并持续跟随，手动拖动后保留自选中心。还提供全景/近景和放大面板；窄屏将场景放到分析区上方。太阳时刻、已有树、确认后的新增树及优化前后切换与二维场景共用数据。3D 目前仅支持这张图。

太阳默认从 09:00 自动播放至 20:00，停留一秒后回到 09:00 循环，速度为每秒 10 个模拟分钟；可暂停或拖动时刻。沿真实步道自动选择约 287 米的连通示范路线，行人以 6 倍速度移动，抵达终点后停下，新一轮太阳循环回到起点。可切换跟随行人、全景、近景；候选路网也能预览行走，尚未确认的道路不进入预算优化。状态与路线遮荫率沿用球形树冠计算模型；不规则叶簇是视觉表达。地面从底图提取草地、铺装、水体等地表类型，不再贴入原图树木符号或固定暗影；动态投影仅来自一盏太阳方向光。

该图的建筑轮廓由像素描摹，W 形和弧形建筑按凸片拆分以保留庭院。图宽暂按 900 米，楼高为 9–15 米、树冠中心高为 8 米；均为待校准假设，不表示清华大学真实测绘。模型在 data/tsinghua-plan.json，底图在 examples/校园道路绿植识别底图.png。渲染采用本地 Three.js；许可证见 vendor/THREE-LICENSE.txt。

## 校园定位

主界面只保留校园名称与日期，不需要填写经纬度、气温、湿度或风速。输入学校全名和城市，点击“定位校园”；有多个结果时选择对应校区。

自动定位需要**本地 HTTP 预览和网络连接**：在项目目录运行 `npm start`，打开 `http://127.0.0.1:4198/`。定位使用 OpenStreetMap 和 Open-Meteo 查询校园坐标及时区，只进行校名及位置查询，不上传校园图片。直接双击离线 HTML 仍可导入底图和计算，但不能联网定位；未定位时使用明确标注的示例位置。

## 模型与数据边界

内置校园、天气、人流和树价是合成示例。导入底图和人工确认的步道可替换示例几何，但比例、树冠、建筑高度及校园位置仍需要现场资料校准。所有遮荫与温度结果均为**模型输出，非实测**。示例树价为 $95/棵，不是供应商报价。

太阳位置使用 NOAA 公式，阴影由建筑与球形树冠几何计算。步道按采样点抵达时刻计算暴露；贪心优化逐棵选择单位费用的新增荫凉收益最大的树。91% 方案为保留满方案至少 91% 新增收益的最短前缀，不保证全局最优。

UTCI 使用官方六阶多项式近似。网页采用固定气象假设：气温 **32°C**、相对湿度 **55%**、10 米高度风速 **1.2 m/s**，辐射输入由示例模型估计；这些参数不再作为主界面的输入控件。UTCI 仅用于方案对比，不能替代真实环境测量。

## 导出与继续编辑

在“路线与预算”中导出 `campus.json`，包含米制坐标、步道网络、建筑、树木、位置与场景参数。坐标 x 向东、y 向北。重新导入导出的 JSON 可恢复保存的方案；新增树与既有树使用独立 ID 标识，避免将新增树算入基线。

当前编辑状态刷新后不会自动恢复，重要方案请导出保存。JSON 是数据文件，不包含自动执行指令。未实现 Godot 互通。

## 本地开发

需要 Node.js 18 或更新版本，无需安装包。Three.js 0.180.0 已随项目保存在 vendor/，构建时内嵌；3D 需要支持 WebGL2 的浏览器。

```sh
npm run build
npm start
```

构建合并 `src/` 中的界面、样式和脚本，输出 `ShadePath-preview.html`、`preview/ShadePath-preview.html` 与 `dist/index.html`。修改源码后重新构建并刷新。`npm start` 只监听本机 `127.0.0.1:4198`，按 Ctrl+C 结束。

详见 [方法学说明](docs/methodology.md)。用户原始说明保存在 [产品说明文档](docs/产品说明文档.md)；其中历史数字和 Godot 内容不代表本次交付状态。

新增行道树候选限制在路缘外 0.3–2 米，保持建筑避让、树间距、全路网收益与公共树只计一次。未确认的识别路网现在也会在后台生成预算内种植预览（不自动确认道路）；地图与 3D 共用同一批树位和编号。自动太阳循环保留一套固定种植方案以展示全天树影变化；手动改变时刻或点击“优化此时刻”重新求解。3D 的“查看新增树”定位实际新增遮荫路段；优化前/后在同一条示范路线、同一时刻和位置比较。示范路线的遮荫比例属于局部效果，不能代替全路网指标。
